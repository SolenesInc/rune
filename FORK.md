# SolenesInc/rune

This fork carries the patches attn's native app needs on top of upstream
[anomalyco/rune](https://github.com/anomalyco/rune). The `attn` branch is
upstream's `dev` with these patches; upstream is merged into it weekly and it is
never rebased. attn's `docs/internal/rune-fork.md` has the rules.

A patch belongs here only when an app cannot do the job through Rune's public
API or the raw window handle. Each line says what the patch changes, why the app
cannot do it, and its test. Remove a line, and its patch, once upstream makes
the patch unneeded.

| Patch | Why the app cannot do it | Test |
|---|---|---|
| A press that reaches a just-shown overlay before its first frame lays out the view first, so the press and its drag reach the element under the pointer (`overlay/input.rs`, `overlay/lifetime.rs`) | The overlay's event order is inside Rune; the app sees no press at all | `overlay::tests::a_press_before_the_first_frame_after_show_reaches_the_view` |
| An overlay that gives its GPU back when hidden removes its CAMetalLayer from the view, which otherwise keeps the last drawable (macOS, `overlay/surface.rs`, `platform/macos/surface.rs`) | The surface and its layer are Rune's | `platform::macos::surface::tests::a_released_surface_leaves_no_layer_in_its_view` (macOS) |
| The macOS app menu names the app from the bundle (`CFBundleDisplayName`, then `CFBundleName`, then the process), for Rune's app items and for winit's default menu, which Rune now adopts and labels (`native_menu/`) | Rune builds and relabels the app menu; an app's own titles are overwritten | `native_menu::standard::tests::the_app_is_named_as_appkit_names_it` |
| `Menu::label` names an open menu for accessibility, as the menu button that opens it does (`rune-kit/src/menu.rs`) | The menu's frame is built inside `Menu::build` and pushed into the layer; the app has no element to name | `menu::tests::an_open_menu_carries_its_label_as_its_accessible_name` |
| `RUNE_OVERLAY_FRAME_LOG=FILE` writes one JSON line per presented overlay frame: name, time since the first, and `draw_frame` time in ms (`overlay/draw.rs`) | Overlays have no `on_frame_encoded`, and `RUNE_FRAME_LOG` covers windows only | `overlay::tests::each_presented_frame_is_one_line_in_the_log` |
| A `Tx::live_only` event owes the next frame only when the scene binds live values; without any, the live lane stayed pending and the window drew every frame until the next commit (`runtime/motion/live_check.rs`, `runtime/input/physical.rs`) | The live lane is Rune's; an app that handles keys live-only cannot clear it | `runtime::live_only_tests::a_live_only_key_in_a_view_without_live_values_leaves_no_frame_owed` |
| `AppHandle::inspect` runs a closure with a live window's `Runtime` on the UI thread, after the queued updates, and handles the input it queues before the next inspection, without waiting for a frame, so a covered window takes it too; it builds what changed before the closure reads, since a covered window builds no view until it shows; the drain asks for a frame only when an inspection built, handled input or changed the view (`app.rs`, `window/lifecycle.rs`) | `AppHandle::update` reaches only the app's state; a running window's element tree, accessibility tree and input queue are the runtime's, and `on_frame_drawn` sees them read-only and only on drawn frames | `window::tests::an_inspection_s_input_is_handled_before_the_next_inspection_reads`, `window::tests::an_inspection_reads_the_view_an_update_built_without_a_frame` |
| A key's frame builds before taking a drawable, as a timer's does, and presents nothing when it draws what is on screen; `Compositor::redraws` (default `draws_own`) lets a compositor window skip it too. Before, every key press presented a frame, so a terminal's echo waited a display refresh behind it (`window/events.rs`, `window/pacing.rs`, `window/draw.rs`, `window/presented.rs`, `compose.rs`) | Which frame takes a drawable is decided inside the window's draw; the app can't keep a key from asking for one | `window::tests::a_key_that_changes_nothing_on_screen_presents_no_frame` |
| `El::pointer_buttons` takes the secondary button: an element that names it hears its press, drag and release through `on_drag` and `on_press`, with `Tx::button` saying which, and opens no menu for it; an element inside with its own `on_secondary_press` keeps its menu. `Tx::pointer_held` tells an `on_pointer_move` handler whether a button was down, on any element, when the pointer moved (`runtime/input/gesture.rs`, `runtime/input/pointer.rs`, `runtime/input/action.rs`, `input/canvas_input.rs`, `el/tx.rs`). A window's right button goes through it too, so a real right-click reaches such an element and still opens another's menu (`window.rs`, `window/events.rs`). A terminal reports both to a program that tracks the mouse, and opens its own menu | The secondary button reaches an app only as a menu request at release, and the press capture is the runtime's | `runtime::gesture_dispatch::tests::an_element_that_takes_the_secondary_button_hears_its_press_drag_and_release_and_opens_no_menu`, `runtime::gesture_dispatch::tests::pointer_motion_says_whether_a_button_is_down_on_any_element`, `window::tests::the_right_button_reaches_an_element_that_takes_it_and_opens_the_menu_of_one_that_does_not` |
| `Tx::open_uri` opens a link of any scheme natively, such as a `file:` URL or `ssh:`, with the same malformed-link checks as `open_url`, and headless runs record it with the others (`open_url.rs`, `el/tx.rs`). A terminal opens the paths and links its output names, as attn's Tauri terminal does | `Tx::open_url` refuses every scheme but `http:`, `https:` and `mailto:`; an app that spawned `open` or `xdg-open` itself would skip the headless record its wire tests read | `open_url::tests::open_uri_takes_any_scheme_natively_and_still_refuses_malformed_links` |
| `App::headless_runtime` installs the app's `App::on_modifiers` hook, as a window does (`playground/testing.rs`). A wire test of a terminal holds ⌘ or Ctrl over a link and sees the pointing hand | The headless runtime is built inside Rune; it installed `on_focus` and `on_ime` but left `on_mods` unset, so no test could hear a modifier change | `playground::testing::tests::a_headless_runtime_tells_the_app_when_the_held_modifiers_change` |
| `El::modal_press_through` lets the pointer reach what is behind a modal that closes on an outside press: the press asks the modal to close and goes on to the element under it, and hover follows the pointer there; a press on the element the modal is anchored to leaves the modal to that element's press instead, as a popover's invoker toggles it; focus and keys stay trapped in the modal (`el/focus.rs`, `runtime/input/focus.rs`, `runtime/input/pointer.rs`, `runtime/input/hit.rs`, `runtime/input/hover.rs`, `runtime/input/gesture.rs`). A pinned tile-header popover closes on a press on another header control or the terminal, and that press lands there, as a light-dismiss popover's does, while a second press on its own trigger closes it | A modal's outside press is swallowed inside Rune's pointer handling, and the hit list leaves out everything behind the modal, so the app never sees the press | `runtime::tests::modal_press_through::a_press_outside_a_press_through_modal_closes_it_and_presses_what_is_under_it`, `runtime::tests::modal_press_through::a_press_outside_a_modal_only_closes_it_by_default`, `runtime::tests::modal_press_through::a_press_on_a_press_through_modals_invoker_leaves_the_modal_to_the_invoker` |
| A `Tx::element_at` callback (and its `_in`, `_with`, `_in_with` forms) runs on the frame's clock, as its handler does, with the window's held modifiers, focus and trace; before, a frame and a key observed at rest ran it with a blank `Tx` whose `clock()` was 0, so a deadline it stamped had already passed (`runtime/frame.rs`, `runtime/input/physical.rs`). A notice posted from a drag's drop pick stays up its full time | The `Tx` a pick-read callback gets is built inside Rune's frame | `runtime::tests::pick_reads::a_pick_read_callback_runs_on_the_frame_clock_its_handler_saw` |
